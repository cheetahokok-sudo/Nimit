# incoming/ — บันทึกจากหนังสือที่ถือครอง

ที่เก็บไฟล์ `.tsv` ที่พิมพ์จากหนังสือ ก่อนแปลงเป็น SQL ด้วย
`scripts/import-book-numbers.mjs`

## ไฟล์ .tsv ห้ามขึ้น repo สาธารณะ

`.gitignore` กันไว้แล้ว เหลือแค่ `TEMPLATE.tsv` ที่ว่างเปล่า

เหตุผล: การพิมพ์ตารางเลขของหนังสือทั้งเล่มออกมาอย่างเป็นระบบ ต่อให้แต่ละบรรทัด
เป็นข้อเท็จจริง แต่รวมกันแล้วใกล้เคียงกับการทำสำเนาฐานข้อมูลของหนังสือ
นโยบายที่บันทึกไว้ตั้งแต่ต้นคือ payload การนำเข้าเก็บใน repo ส่วนตัวหรือในเครื่อง
ส่วน **สคริปต์** อยู่ใน repo สาธารณะได้ เพราะสคริปต์ไม่ใช่ทรัพย์สิน — คลังต่างหากที่ใช่

## รูปแบบไฟล์

TAB คั่นคอลัมน์ บรรทัดละหนึ่ง (สัญลักษณ์ + หน้า)

```
หน้า	คำ	เลข	ความหมายสั้น
12	ช้าง	91,19,019	ดี ได้ผู้ใหญ่อุปถัมภ์
12	ช้างเผือก	91,019	ดีมาก ลาภใหญ่
13	งูเหลือม	56,65	ได้คู่ มีคนหลงรัก
```

- **หน้า** — เลขหน้าในเล่ม ต้องมีทุกบรรทัด เพื่อให้ตามกลับไปเปิดตรวจได้
- **คำ** — คำที่หนังสือใช้ ถ้าคำนั้นยังไม่มีในคลัง สคริปต์จะรายงานให้ทราบ
  และ **ไม่บันทึกเลขของคำนั้น** จนกว่าจะเพิ่มสัญลักษณ์ก่อน
- **เลข** — คั่นด้วยจุลภาค 1–3 หลัก **เก็บศูนย์นำหน้าไว้เสมอ** (`09` ไม่เท่ากับ `9`)
- **ความหมายสั้น** — ไม่บังคับ 3–8 คำพอ เขียนด้วยสำนวนของเราเอง

## ⚠️ ใช้ text editor เท่านั้น อย่าใช้ Excel หรือ Google Sheets

โปรแกรมตารางจะแปลง `09` เป็น `9` เงียบ ๆ และ `09` กับ `9` เป็นคนละเลขกันในการตรวจหวย
นี่คือความเสียหายที่มองไม่เห็นและเกิดกับคอลัมน์ที่งานทั้งหมดนี้ทำขึ้นมาเพื่อเก็บ

ใช้ Notepad, VS Code หรืออะไรก็ได้ที่บันทึกเป็น **UTF-8**

## ขั้นตอน

```bash
node scripts/import-book-numbers.mjs supabase/seeds/incoming/fan-phayakon.tsv > /tmp/numbers.sql
```

แล้วนำ `/tmp/numbers.sql` ไปรันใน Supabase SQL Editor

ทุกแถวจะเข้าเป็น **draft** เสมอ — ยังไม่แสดงในแอป

## ทำไมต้อง draft

ความเชื่อที่ปรากฏในหนังสือเล่มเดียวคือ *สำนวนของสำนักพิมพ์นั้น*
ความเชื่อเดียวกันที่ปรากฏตรงกันในหลายเล่มคือ *ข้อเท็จจริงทางวัฒนธรรม* ซึ่งไม่มีใครเป็นเจ้าของ

การรอแหล่งที่สองจึงไม่ใช่ความขี้ระแวง แต่เป็นสิ่งที่เปลี่ยนสถานะทางกฎหมายของเนื้อหา
และทำให้คำทำนายที่แสดงในแอปน่าเชื่อถือกว่าเดิมด้วย

เมื่อมีแหล่งที่สองแล้ว ค่อยเปลี่ยนเป็น `published` พร้อมบันทึก
`corroborating_edition_ids`
